csagent

Agent d'assistance au codage autonome multi-plateformes

Présentation (vidéo)

csagent est conçu pour aider les agents de l'administration à automatiser leurs tâches de développement informatique, sans recours aux LLM publics.

Usage restreint. Cette solution est destinée aux environnements où les services cloud publics (ChatGPT, Claude, etc.) sont interdits. csagent peut être configuré avec des modèles locaux ou privés.

Fonctionnalités

  • Multi-plateforme — Windows, Linux et macOS
  • Compatible OpenAI — tout LLM exposant une API compatible (par défaut : Qwen3-Coder via ALBERT/Etalab)
  • Gestion de fichiers — lecture, écriture, exploration de répertoires
  • Exécution de commandes — shell avec gestion des codes de retour
  • Sessions persistantes — historique stocké dans un fichier JSON
  • Modes sécurisés — --dry-run et --confirm pour prévisualisation et validation

Utilisation

csagent <fichier-mémoire> [<prompt-ou-fichier>] [options]

Arguments

ArgumentDescription
fichier-mémoire Fichier JSON de l'historique. Créé automatiquement à la première exécution.
prompt-ou-fichier Tâche sous forme de chaîne, ou chemin vers un fichier texte. Omettre pour reprendre une session.

Options

OptionDescription
--dry-runAffiche les appels d'outils sans les exécuter.
--confirmDemande confirmation avant chaque commande shell ou écriture.
--max-steps NNombre maximum d'itérations (défaut : 30).
--model NOMRemplace le modèle LLM (défaut : Qwen/Qwen3-Coder-30B-A3B-Instruct).
--endpoint URLRemplace l'URL de base de l'API.
--helpAffiche l'aide.

Exemples

Première exécution

csagent.exe memory.json "Écrire un serveur HTTP Python qui sert le répertoire courant."

Tâche depuis un fichier

csagent.exe memory.json task.txt

Reprendre une session

csagent.exe memory.json

Mode aperçu (sans exécution)

csagent.exe memory.json "Refactoriser main.py" --dry-run

Mode confirmation

csagent.exe memory.json "Nettoyer tous les fichiers .tmp" --confirm

Modèle personnalisé

csagent.exe memory.json "Ajouter des tests unitaires" \
    --model gpt-4o \
    --endpoint https://api.openai.com/v1

Outils disponibles

OutilDescription
write_file(path, content)Crée ou écrase un fichier UTF-8. Répertoires parents créés automatiquement.
read_file(path)Lit et retourne le contenu d'un fichier (limite : 512 Ko).
list_dir(path?, recursive?)Liste fichiers et sous-répertoires.
sh(cmd)Exécute une commande shell (cmd.exe / /bin/sh). Timeout : 60 s. Code de sortie rapporté.

Configuration

Prérequis

  • SDK .NET 8 — dotnet.microsoft.com
  • Clé API pour un endpoint compatible OpenAI
  • Par défaut : ALBERT (Etalab) — variable ALBERT_API_KEY
  • Autre API compatible — variable OPENAI_API_KEY

Clé API

# Linux / macOS
export ALBERT_API_KEY=your-key-here

# Windows (cmd)
set ALBERT_API_KEY=your-key-here

# Windows (PowerShell)
$Env:ALBERT_API_KEY = "your-key-here"

Sécurité

Attention. La commande sh exécutera toute commande décidée par le modèle. Utilisez --confirm dans un espace de travail sensible.
  • Utiliser --dry-run pour auditer avant exécution
  • Ne jamais stocker la clé API dans memory.json ou un fichier suivi
  • Garder le fichier de mémoire hors des répertoires contenant des secrets
